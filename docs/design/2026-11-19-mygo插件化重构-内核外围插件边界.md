# mygo 插件化重构经验沉淀（内核/外围插件边界）

> 日期：2026-11-19 ｜ 项目：mymusic/mygo ｜ 类型：架构探索
> 主题：把 mygo 从「单机 B站播放器」升级成「插件化现代播放器框架」，确立内核/外围插件边界

## ① 目标与动机

mygo 是 MyGo（Go 优先跨平台桌面 UI 框架）写的原生播放器，作为 mymusic 项目**第二入口**（与主线 `go/` web 版并存）。目标：**解耦音源/歌词/目标/插件系统，UI 完全由插件派生**，核心原则：

1. **一切皆插件**——音源/歌词/目标/本地播放/蓝牙全插件化，插件零耦合
2. **内核 + 外围插件**——系统内部是一个稳定内核，外围是可插拔插件
3. **复用主线**——不造轮子，能复用主线域包/api 就复用
4. 未来**多端**（安卓/WASM）复用核心，只换 UI

## ② 资源拓扑（架构成果）

### 分层：内核 vs 外围插件

```
┌─────────────────────────────────────────────────────┐
│ 内核（系统之本，固定，不可插拔）                          │
│  · 播放核心（playback 状态机，主线域包）                   │
│  · 队列/SSOT 状态                                      │
│  · UI 骨架（导航/播放条/内容槽/布局原语/视觉原语）           │
│  · 缓存服务（歌曲/歌词，被插件共享使用，非插件）              │
│  · 网络/持久化/窗口/事件循环                             │
├─────────────────────────────────────────────────────┤
│ 外围插件（可插拔，内核留槽）                              │
│  · 音源（B站/网易云/本地/未来）                           │
│  · 歌词（网易云/未来）                                   │
│  · 目标（本机声卡/DLNA/蓝牙/小爱音箱/未来）                │
│  · UI 扩展（目标面板/插件配置子页）                       │
└─────────────────────────────────────────────────────┘
```

**关键边界判断**（用户拍板）：
- **缓存 = 内核服务**，不是插件。缓存是"被所有插件共享使用的基础能力"（被用的服务），不是"被插拔的扩展点"。做成插件会重复造轮子、无法统一上限/淘汰/清理。
- **音质 = 源控制**，不是系统设置。音质是音源专属（B站低/中/高档），归音源插件配置。
- **歌词设置 = 歌词插件配置**，不是系统设置。歌词字号/背景/时间显示/偏移归网易云歌词插件。

### 插件 API 全貌（mygo/plugin/）

| 能力 | API | 说明 |
|---|---|---|
| 音源 | `RegisterSource`/`Sources`/`SourceNames` | 实现 `source.MusicSource`（Search/GetStream/GetLyric） |
| 歌词 | `RegisterLyric`/`Lyric`/`LyricNames` | 实现 `lyric.Provider`（Fetch） |
| 目标 | `RegisterTarget`/`Targets` | 实现 `target.Target`（Play/Stop），设备实例 |
| 元数据 | `RegisterInfo`/`InfoNames`/`SetEnabled`/`IsEnabled` | 插件页列表/开关/展示顺序（`Info.Order`） |
| 目标面板 | `RegisterTargetPanel`/`TargetPanels`/`TargetPanelHost` | 目标页派生（依赖反转，面板只认接口） |
| 稳定链路 | `plugin.Link`（`linkCore` 实现） | 搜索→播放→控制→歌词统一入口，多端复用核心 |

**注册表模式**：map + 接口 + init 注册（编译期注册，无 cgo）。新增插件类型 = 定义接口 + 一个 `RegisterXxx` + 插件页加分组，**不改核心逻辑**。

```go
// 1. 实现接口（如 source.MusicSource）
type MySource struct{}

// 2. init() 注册
func init() { plugin.RegisterSource(MySource{}) }
// 3. 主程序 import _ "包路径" 启用
```

## ⑤ 踩坑记录

### 坑 1：目标页/插件页"前后不一"
- **现象**：目标页有 DLNA/蓝牙/音箱面板，但插件页"输出目标"看不到它们。
- **根因**：`main.go` 只注册了 bilibili/netease/local 三个固定元数据（`RegisterInfo`），DLNA/蓝牙/音箱**没注册为固定条目**（只在设备被发现时才 RegisterTarget 设备实例）。
- **解法**：把 cast/bluetooth/speaker 注册为固定 target 元数据（设备无关的"目标种类"），与 local 并列。

### 坑 2：插件页条目上下跳动
- **现象**：插件页插件项一直动来动去，上下移动。
- **根因**：`plugin.InfoNames` 用 `for range map` 遍历 `infos`（`map[string]Info`），**Go map 遍历顺序随机** → 每次重绘（Invalidate）顺序都变。
- **解法**：`Info` 加 `Order int` 字段，`InfoNames` 显式按 `Order` 排序（不再依赖 map 随机遍历）。注册时填 Order（bilibili=10/netease=20/local=30/cast=40/bluetooth=50/speaker=60）。

### 坑 3：目标页顶部冗余标题
- **现象**：目标页顶部有"目标"大标题，但导航已叫"目标"。
- **解法**：删页内标题（导航项名已表达，页内不重复）。

### 坑 4：小爱音箱登录归属
- **现象**：小爱音箱登录态在目标页显示，但登录是插件配置。
- **解法**：登录移到插件页（插件卡片显示登录状态行 + 编辑子页做扫码/token/刷新/复制），目标页只留设备投送/停止。

### 坑 5：main 包实现插件接口的循环依赖
- **现象**：`linkCore` 要实现 `plugin.Link`，但 plugin 包不能 import main（循环）。
- **解法**：**依赖反转**——`TargetPanelHost`/`Link` 接口定义在 plugin 包，main 包的 app 实现接口，回调只认接口不认具体类型。编译期断言 `var _ plugin.Link = (*linkCore)(nil)` 保证完整实现。

### 坑 6：测试取不到注册的音源/目标
- **现象**：`TestLinkSources`/`TestLinkTargets` 失败（注册表为空）。
- **根因**：RegisterSource/RegisterTarget 在 app 初始化才调（依赖 a.svc.music / a.mygoOut），测试不跑 app 初始化。
- **解法**：测试里用**假实现**（fakeSource/fakeTarget）手动注册，验证 linkCore 经注册表取到音源/目标。

## ⑦ 决策记录

| 决策 | 选 A 不选 B 的原因 |
|---|---|
| 缓存=内核服务，非插件 | 缓存是共享基础能力（被用的服务），不是扩展点；做成插件重复造轮子、无法统一上限/淘汰/清理 |
| 音质=源控制 | 音质是音源专属档位，归音源插件配置，不进系统设置 |
| 歌词设置=歌词插件 | 字号/背景/时间显示/偏移是网易云专属，归歌词插件配置 |
| 目标页=插件派生 | 枚举 `plugin.TargetPanels()`，面板只认 `TargetPanelHost` 接口（依赖反转），第三方可独立实现 |
| Link 不依赖 UI | `linkCore` 只持 playback 状态机 + 注册表，任何端（安卓/WASM）可独立 `NewLink(pb)` 构造复用核心 |
| 注册表=map+init | 编译期注册（无 cgo），插件零耦合；未来可扩展 .so/WASM 动态加载 |
| **EQ/音效=插件，但内核留效果链插槽** | 效果算法/参数随音效种类变化，内核不该知道每种实现；但插件要影响播放音频必须挂进内核音频管线，所以**内核提供 EffectChain 插槽 API + 插件实现 Effect**（同构于"目标插件 + 内核投送链路"） |

**放弃的方案**：不做插件动态加载（.so/WASM 目前），先编译期注册；不做"缓存插件"（用户明确缓存归内核）。

## ⑧ 未解之谜 / 下一步岔路

1. **体验优化功能（EQ/均衡器/音效）**——**已决：插件**（算法+参数各实现 Effect），但**内核需预留音频效果链插槽 API**（`EffectChain` + `RegisterEffect`），不能纯插件/纯内核。未实现。
2. **插件动态加载**（.so/WASM）——`plugin.go` 留了 `LoadFromDir` 注释，未实现
3. **多端复用**——`linkCore` 已可独立构造，但安卓/WASM 端还没写（mygo/android/ 有壳）
4. **插件配置持久化**——`SetEnabled`/pref 已存，但插件自有配置（如网易云偏移）的通用化存储待完善
5. **新音源**（网易云音乐/本地目录）——只定义了接口，B站是唯一实现
