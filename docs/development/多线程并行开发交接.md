> 交接给：并行开发线程（当前 2 线程 → 规划 4 线程）
> 任务：**三线程并行开发**，各线程有独立文件所有权，互不踩脚，共享编译单元用"注册文件隔离"化解

---

## 0. 先读：并行开发的铁律（避免 merge 地狱）

**Go 的 `package main` 所有文件是同一编译单元**——多线程并行改同一包会高频冲突 + 编译互相失败。本文档的边界设计就是为此：

1. **文件所有权唯一**：每个 `.go` 文件只属于一个线程，绝不同时改他人文件。
2. **共享文件（main.go / plugin.go / ui_modern.go）用"注册文件隔离"**：每个线程的**新增注册**放自己独占的 `register_<域>.go`，main.go 只保留启动调用（见 §2.2）。
3. **提交前自验**：每个线程必须 `GOFLAGS="-mod=mod -tags=native" go build ./...` 通过（整包编译共享，但各自保证自己改动可编译）。
4. **子包独占**：`source/`、`target/`、`plugin/`、`lyric/`、`plugins/` 各子包只归一个线程维护。
5. **git 策略**：每线程独立分支（`t1-<feature>` / `t2-<feature>` / `t3-<feature>`），合并回 `master` 由协调者做；**不并行 rebase master**（会互相覆盖）。

## 2. 三线程边界（功能域 + 文件所有权）

### 2.1 线程划分总览

| 线程 | 功能域 | 独占文件/包 | 核心任务 |
|---|---|---|---|
| **T1 音源域** | 音源/歌词/插件系统 | `source/`、`plugin/`、`plugins/`、`register_source.go`、`search_view.go`（仅源切换） | 新音源（本地目录/更多 JS 源）、插件系统维护 |
| **T2 目标域** | 目标/投送 | `target/`、`target_panel_*.go`、`cast_page.go`、`register_target.go` | 新目标（更多投送）、目标面板、投送链路 |
| **T3 内核/UI** | 播放内核/队列/UI | 主包其余 `*.go`、`lyric/`、`register_kernel.go` | 播放、队列、UI 骨架、设置、歌词、滚动条/交互 |

**公共只读**（都不独占，需协调）：`main.go`（启动调用）、`ui_modern.go` 的 `pluginGroup` 调用点、`plugin_page.go` 分区框架、`settings_page.go` 设置框架。

### 2.2 共享文件怎么处理（关键）

**main.go 的注册区拆成三个独占文件**，各线程只碰自己的：

```go
// register_source.go  【T1 独占】
package main
func init() { /* 不 init——用显式调用，见下 */ }
// 实际放 T1 的注册函数：registerSourcePlugins()
// 音源/歌词/插件元数据注册 → 只归 T1

// register_target.go  【T2 独占】
// registerTargetPlugins()：目标/投送注册 → 只归 T2

// register_kernel.go  【T3 独占】
// registerKernel()：playback/mygoOut/streamServer/fav/songlist 装配 → 只归 T3
```

main.go 的 `main()` 里只写**调用**（一行一个，不内联注册逻辑）：

```go
func main() {
    // ... 既有初始化 ...
    registerSourcePlugins()  // T1 的（main.go 不碰实现）
    registerTargetPlugins()  // T2 的
    registerKernel()         // T3 的
    // ... 其余启动 ...
}
```

**原则**：main.go 的注册**调用行**由协调者（T3）加一次后冻结；各线程改**自己的 register_*.go 实现**，不动 main.go。新增插件类型（如 T1 加新音源）只在 `register_source.go` 加 `RegisterSource(...)` + `RegisterInfo(...)`，**不碰 main.go**。

### 2.3 T3 独占文件清单（主包 UI/内核）

`main.go`(启动装配协调)、`main_setting.go`、`player.go`、`player_ctrl.go`、`player_ui.go`、`pb_bridge.go`、`mygo_output.go`、`stream_server.go`、`services.go`、`widget.go`、`scale.go`、`ui_modern.go`、`ui_icons.go`、`navbar.go`、`queue_page.go`、`songlist_ui.go`、`fav_page.go`、`recent_page.go`、`settings_page.go`、`lyric_panel.go`、`lyric_bridge.go`、`link_impl.go`、`web_main.go`、`lyric/`

> ⚠️ 注意：T3 独占 `ui_modern.go` 里的 `pluginGroup(c, "音源", "source")` 调用点**是共享概念**——T1 加音源 / T2 加目标，需要 pluginGroup 出现对应分组。当前 pluginGroup 已按类型分组（source/lyric/target），**T1/T2 新增同类型插件会自动进组**（组按 type 渲染），T3 无需改。只有**新增插件类型**（新 capability）才需要 T3 在 `plugin_page.go` 加分组。

## 5. 已确认决策（勿推翻，除非用户明确改）

| 决策 | 结论 | 依据 |
|---|---|---|
| **插件接入** | 编译期注册（Go，主推）+ JS 沙箱（sobek，已落地）；**WASM ❌ 不做**（用户 2026-11-19 否决） | 沙箱无网络/UI，需大量宿主桥接；TinyGo 受限 |
| **音效/EQ** | **❌ 不做**（用户 2026-11-19 否决） | 主线 web 无音效（HTMLAudio+音量），做=脱离主线造轮子 |
| **Go plugin(.so)** | **❌ 不做** | 要 cgo、仅 Linux/FreeBSD、Go 无稳定 ABI |
| **外部进程 IPC** | **❌ 不做** | 用户明确禁止子进程 |
| **JS 安全三层** | 超时 5s + 并发 8 + allowedHosts 白名单 + JSON 边界 | 学 new-api |
| **播放不改队列** | 歌在队列→只定位 QIdx；不在→追加队尾（主线 playback.Play） | 用户要求"放只改从哪开始" |
| **滚动条** | 全部 `Scrollbars(false)`（滚动功能保留） | 用户嫌常显 |
| **双击/单击** | 播放列表行=双击；最近播放卡片=单击 | 用户要求 |
| **长标题提示** | 原生 `Tooltip(s)`（无覆层） | 用户否决自绘 Overlay 浮层 |
| **缓存=内核服务 / 音质=源控制 / 歌词设置=歌词插件** | 维持 | 已拍板 |
| **一切皆插件** | 音源/歌词/目标/本地播放/蓝牙全插件化；UI 走统一 API 枚举 | 已拍板 |
