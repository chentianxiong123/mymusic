# 登录态持久化审计（2026-11-25）

## 结论速览

| 项 | 之前状态 | 现在 |
|---|---|---|
| Cookie 落盘 | ✅ `settingStore` → SQLite `settings` 表 | ✅ 按平台统一存 `plugin:account/<platform>/cookie`（音源/歌词/推荐共享），老键自动迁移 |
| 启动恢复 Cookie | ✅ B站/网易云 Go 源从设置读；JS 源 `requiresCookie` 检查读同一处 | 不变 |

| 扫码后热更新 | ⚠️ 只有 B站 `a.bili.Cookie` 热更新；网易云 Go 源要重启才生效 | ✅ 统一 `applySourceCookie` + `hotUpdateCookie`（B站+网易云 Go 源 setter） |
| 退出登录 | ❌ **完全没有**，Cookie 无法清除 | ✅ 登录弹窗「退出登录」：清持久 Cookie + 热更新置空 + 停未完成的扫码 |
| 登录有效期/过期检测 | ❌ 没有（只看 cookie 非空=已登录） | ✅ B站/网易云真校验（实测端点+账号名），过期显示红色；其它平台诚实标「已登录」不误报 |

## 实测证据

- 本机 `data.db` 的 `settings` 表无任何 `plugin:` 前缀的 cookie 行（本机从未登录过，符合预期）。
- `plugin/setting.go` 的 `SetSetting` → `settingStore.Set` → `conv.SaveSetting` 走 SQLite，真落盘。
- 回归测试 `TestJSPluginCtxConfigPersistent` 修复前失败（`ctx.config.get 不是函数`/返回空），修复后通过——证明 bug 真实存在且已修。

## 代码落点

- `mygo/plugin/jsplugin.go` `makeCtx()`：`ctx.config` 改为 `jp.host.configObject()`（与 `host.config` 同一对象）。
- `mygo/qr_login.go`：`applySourceCookie`（落库+热更新）、`hotUpdateCookie`、`logoutSource`；登录弹窗加「退出登录」按钮。
- `mygo/plugin_page.go` B站 Cookie 保存改走 `applySourceCookie`。
- `mygo/source/netease.go`：`SetCookie`；`main.go` 保留 `neteaseSrc` 实例引用供热更新。

## 登录态校验（2026-11-25 补做）

- 实测端点：B站 `/x/web-interface/nav`（code=0 && isLogin，带 uname）；网易云 `/api/w/nuser/account/get`（code=200 && account!=null，带 nickname）。无 Cookie 与假 Cookie 都返回明确未登录，校验逻辑可靠。
- 启动时异步校验所有已登录源；保存/扫码/退出后立即重校验。UI 显示「未登录 / 已登录 · 账号名 / 已过期（红）」。
- 网络失败不误判过期（Checked=false → 「已登录」，不吓用户）。

## 未做（诚实边界）

- 酷狗/QQ/咪咕/酷我：没有可靠的"用 WEB Cookie 校验"端点（咪咕 token-validate 用的是兑换前的 passport token，登录后已换成 WEB Cookie），不做假校验，显示「已登录」不加账号名。
- JS 插件的 token/cookie 格式由各插件自己解释，宿主不校验（保持插件自由）。

## 登录态共享（2026-11-25 补做）

问题：插件按能力拆成 source/lyric/recommend 后，登录态存 `plugin:source/<平台>/cookie`，歌词/推荐插件读不到同一份 → 用户得重复登录，平台在插件页出现多次。

方案（不做彻底聚合，只收敛登录态）：
- `plugin/account.go`：`GetCookie/SetCookie/ClearCookie/HasCookie`，按平台名共享，唯一键 `plugin:account/<platform>/cookie`。
- 老用户兼容：老键 `plugin:source/<平台>/cookie` 首次读时自动迁移并清空。
- JS 插件 `ctx.config`/`host.config`/`host.setting` 的 `cookie` 读写、`requiresCookie` 检查全部路由到 account 层。
- Go 侧（扫码/粘贴/启动恢复/过期校验）全部改用 account 层。
- 设置声明（UI 输入框）仍按能力类型保留，但存储统一。

**能力层仍分离**（source 归 source、歌词绑定继续跨源引用），只是登录态按平台共享——避免推翻歌词绑定设计和独立歌词插件的自由。
