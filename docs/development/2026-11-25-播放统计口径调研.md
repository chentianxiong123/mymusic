# 播放统计口径调研（2026-11-25）

## 调研结果

| 软件 | 统计口径 | 来源 |
|---|---|---|
| **QQ音乐「最近播放」** | 每首歌显示播放次数，重复播放计数（放了就算一次），只保留近期数据 | [正软商城](https://www.zhengruan.com/news/738841) |
| **网易云「等级听歌量」** | 单首听满 >60 秒算 1 首；同一首听 N 次仍算 1 首（去重）；每天上限 300 首 | [网易云官方 FAQ](https://music.163.com/topic?id=199001) |
| **Spotify stream** | 播放 ≥30 秒算一次 stream | [Spotify 官方](https://support.spotify.com/us/artists/article/how-your-streams-are-counted/) |
| **Last.fm scrobble** | 听满 30 秒或歌曲一半才计一次 | [Last.fm API](https://www.last.fm/api/scrobbling) |
| 各平台年度报告 | 有总时长，但属于年度运营数据（含播放时间/内容/收藏等维度），不是日常统计 | [网易云年报隐私指引](https://y.music.163.com/g/yida/51c3865231a843f2a98a5821d9affdc7) |

## 决策

**mymusic 采用 QQ音乐「最近播放」口径：播放一次 = 计数 +1，不做时长累计。**

理由：
- 本地统计没有"防刷量/冲榜"需求，60 秒阈值（网易云等级）或 30 秒阈值（Spotify）是为了平台侧结算，本地用只会让数据失真（用户切歌试听不算，但他确实放了）。
- 时长统计需要 250ms 进度差 + 节流落库，实现复杂且易错（暂停/seek/切歌都会多算），和"省资源"原则冲突。
- 播放次数足够驱动"常听歌曲/歌手"和本地推荐，数据结构更简单。

## 代码变化

- `play_stats.go`：去掉 `TotalSec` 字段和 `statsAddSec`，只留 `Count/LastAt/Source/ID/Title/Artist/Cover`。
- `pb_bridge.go`：去掉 250ms 进度差累计逻辑（零额外开销）。
- `stats_page.go`：只显示"累计播放 N 次"，去掉总时长。
- 计数时机：`play()` 入口 +1（放了就算一次）。
